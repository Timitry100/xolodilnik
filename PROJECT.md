## 1. Что это за проект

Telegram Mini App (встроенное приложение в Telegram) для учёта продуктов в холодильнике.
Пользователь сканирует продукт камерой через приложение, система распознаёт товар,
сохраняет **название, КБЖУ, состав и срок годности**, следит за сроками и предупреждает о просрочке.

## 2. Требования (от пользователя)

1. Сканирование **«Честного знака»** (Data Matrix на упаковке) камерой → распознавание товара.
2. В карточку продукта заносятся: что за товар, КБЖУ, состав, **главное — срок годности**.
3. **Предупреждения о сроках годности** (цветовые метки + уведомления от бота).
4. **Сортировка и удобное меню**.
5. Если QR «Честного знака» нет → сканировать **обычный штрихкод** и подтягивать инфо из открытых данных.
6. Если и штрихкода нет → **автоматическая считка текста** с упаковки (OCR).
7. Файл `PROJECT.md`, в котором ИИ каждый раз пишет, что сделал, и хранит всю информацию о проекте.

## 4. Стек технологий

- **Бэкенд:** Node.js 24 (ESM), Express, `node-telegram-bot-api` (polling)
- **База данных:** встроенный `node:sqlite` (без компиляции на Windows)
- **Фронтенд:** React 18 + Vite, HashRouter, Telegram WebApp SDK
- **Сканирование:** `@zxing/library` (DataMatrix, EAN-13, QR), `BarcodeDetector`, `Tesseract.js` (rus+eng)
- **Открытые данные:** Open Food Facts API (`world.openfoodfacts.org`)
- **Хостинг:** VPS Windows 10, один процесс Node.js отдаёт API + собранный фронтенд

## 7. Как запустить локально

**Самый простой способ — двойной клик по `start.bat`**: проверит Node.js, создаст `server/.env`,
попросит токен бота (если его нет), установит зависимости, соберёт фронтенд и запустит сервер.
Дополнительно `start.bat` запускает **джоб автообновления**: каждые 2 минуты он проверяет Git,
и если в репозиторий запушены новые изменения — сам подтягивает их, пересобирает приложение
и перезапускает сервер. Подробнее — в разделе 16.

Вручную:

```bash
# 1. Установить зависимости
cd server && npm install
cd ../app && npm install

# 2. Создать бота в @BotFather, получить токен
#    Скопировать server/.env.example → server/.env, вписать BOT_TOKEN

# 3. Запустить бэкенд (терминал 1)
cd server && npm run dev

# 4. Запустить фронтенд с горячей перезагрузкой (терминал 2)
cd app && npm run dev
#    Mini App откроется на http://localhost:5173

# 5. Для проверки на телефоне — пробросить порт 5173 через ngrok:
ngrok http 5173
#    Затем в BotFather (Menu Button) указать https-адрес ngrok, и у бота
#    в .env поставить APP_URL на этот же адрес.
```

Продакшен-сборка (одним процессом):

```bash
cd app && npm run build     # собирает фронтенд в app/dist
cd ../server && npm start   # сервер сам раздаёт app/dist на порту 3001 (3000 занят первым сайтом)

| `TG_PROXY` | Прокси для бота, если Telegram заблокирован (РФ). Пример: `http://127.0.0.1:10809` (HTTP-прокси v2rayN) |

## 9. База данных (SQLite, файл `server/data/xolodilnik.db`)

- **users** — пользователи: `id, telegram_id (unique), chat_id, name, created_at`
- **products** — продукты: `id, user_id, name, brand, category, kcal, protein, fat, carbs, composition, expiry_date (YYYY-MM-DD), barcode, gtin, serial, source ('honest_sign'|'barcode'|'ocr'|'manual'), image_url, note, quantity, created_at, updated_at`
- **notifications** — отправленные предупреждения: `id, product_id, level ('d7'|'d3'|'d1'|'expired'), sent_at` (чтобы не спамить повторно)

## 10. REST API

Все запросы требуют заголовок `X-Init-Data` (подпись Telegram WebApp, проверяется HMAC-SHA256).

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/me` | Профиль пользователя |
| GET | `/api/products` | Список продуктов пользователя |
| POST | `/api/products` | Создать продукт |
| GET | `/api/products/:id` | Детали продукта |
| PUT | `/api/products/:id` | Изменить продукт (например, продлить срок) |
| DELETE | `/api/products/:id` | Удалить продукт |
| POST | `/api/products/:id/consume` | «Я съел»: количество −1, при нуле продукт удаляется |
| POST | `/api/recipes/generate` | Рецепты нейросетью/локальной базой. Body: `{mode: 'own'|'suggest', level: 'fast'|'medium'|'gourmet'}` |
| GET | `/api/honest-sign/:gtin` | Данные товара по GTIN «Честного знака» (ЦРПТ → фолбэк Open Food Facts) |
| GET | `/api/stats` | Статистика: всего, просрочено, истекает скоро |

Дополнительно сервер раздаёт собранный фронтенд из `app/dist` (продакшен).

## 11. Внешние сервисы

- **Open Food Facts** — `https://world.openfoodfacts.org/api/v2/product/{ean}.json`.
  Отдаёт название, бренд, категорию, КБЖУ (nutriments), состав (ingredients_text_ru), картинку.
  Запрос делается прямо из браузера (CORS разрешён). Работает с EAN-13; GTIN «Честного знака» (14 цифр) приводится к 13-значному EAN удалением ведущих нулей.
- **«Честный знак»** — Data Matrix на упаковке содержит URL вида
  `http://datamatrix.nalog.ru/1/{GTIN}/{серийный}/{код}`. Декодируем Data Matrix в браузере
  (`@zxing/library`), вытаскиваем GTIN и ищем товар в открытых данных. Публичный API ЦРПТ
  требует авторизации, поэтому для MVP используется Open Food Facts по GTIN.
- **OCR** — `Tesseract.js` (языки `rus+eng`) прямо в браузере, без серверного CPU.
  Из распознанного текста регулярными выражениями извлекаются: срок годности
  («годен до 25.08.2026», «срок годности 6 месяцев»), КБЖУ («белки 3,2 г» и т.д.), состав.
- **API «Честного знака» (ЦРПТ)** — официальный API `ismp.crpt.ru/api/v3`
  (OAuth client_credentials, требуются ключи из ЛК ЦРПТ). Полный доступ к данным товаров
  (в т.ч. молочной продукции) даёт только авторизованный API. Без ключей используется
  публичная проверка кода ГИС МТ/ФНС (`apic.datamatrix.nalog.ru`) + фолбэк Open Food Facts.
- **ИИ для рецептов** — OpenRouter (`https://openrouter.ai/api/v1`), модель по умолчанию
  `deepseek/deepseek-chat:free`. Промпт требует JSON: рецепты, ингредиенты (есть/купить),
  шаги, список докупки. При отсутствии `AI_API_KEY` — локальная база из 28 рецептов
  (`server/src/recipes.js`) с подбором по совпадению ингредиентов.

## 12. Telegram: создание бота и настройка Mini App

1. В Telegram открыть **@BotFather** → `/newbot` → получить `BOT_TOKEN`.
2. В BotFather: `/mybots` → выбрать бота → **Bot Settings → Menu Button** →
   указать URL Mini App (https-адрес приложения). Кнопка «Открыть приложение» появится в чате.
3. Mini App откроется в Telegram, и в него прилетит `initData` — им фронтенд
   авторизуется на сервере (заголовок `X-Init-Data`, проверка HMAC-SHA256 по токену бота).
4. Для уведомлений о сроках бот работает в режиме **polling** (сам забирает апдейты,
   публичный webhook не нужен) — удобно для VPS за NAT.

## 13. Деплой на VPS (Windows 10)

### Вариант A — nginx (если первый сайт уже на nginx)

Один сервер может отдавать несколько сайтов: разные домены на один IP.
Для «Холодильника» понадобится свой поддомен (например `app.твой-домен.ru`):

1. В панели DNS: A-запись `app` → статичный IP сервера.
2. Добавить в `nginx.conf` (секция `http {}`) готовый блок из
   **`deploy/nginx-xolodilnik.conf.example`** (прокси на `127.0.0.1:3001`).
   Сертификат — переиспользовать wildcard от первого сайта или выпустить новый.
3. `nginx -t` → `nginx -s reload`.
4. Запустить `start.bat` (сервер на порту 3001; порт 3000 занят первым сайтом bobkoved.ru).
5. `APP_URL=https://app.bobkoved.ru` в `server\.env`, указать тот же адрес в BotFather (Menu Button).
6. Порт 3001 наружу НЕ открывать — всё идёт через nginx по 443.

### SSL-сертификат для поддомена (win-acme)

Сертификат первого сайта (`bobkoved.ru`) не покрывает поддомен `app.bobkoved.ru`
и может быть выдан недоверенным центром — для Telegram нужен публичный Let's Encrypt:

1. Создать папку `C:\acme`.
2. В nginx добавить **HTTP-блок** с `location /.well-known/acme-challenge/`
   (Блок 1 из `deploy/nginx-xolodilnik.conf.example`), `nginx -s reload`.
3. Скачать win-acme (**https://www.win-acme.com/**), распаковать, запустить `wacs.exe`.
4. В меню: `N` → домен `app.bobkoved.ru` → способ **Webroot** → путь `C:\acme`
   → установка **PEM files** → папка `C:\acme\certs` → создать задачу планировщика
   (автопродление каждые ~60 дней).
5. В nginx добавить **HTTPS-блок** (Блок 2 из шаблона) с путями
   `C:/acme/certs/app.bobkoved.ru/certificate.pem` и `privkey.pem`.
6. `nginx -t` → `nginx -s reload`, проверить `https://app.bobkoved.ru` с телефона.
7. Порт 80 должен быть открыт наружу (иначе проверка домена не пройдёт).

### Вариант B — Caddy (бесплатный HTTPS, сам выпускает сертификаты)

```
app.твой-домен.ru {
    reverse_proxy localhost:3000
}
```

### Вариант C — IIS (если первый сайт на IIS)

Новый сайт в IIS + Reverse Proxy (URL Rewrite) на `http://localhost:3000`.

### Общие шаги (после настройки прокси)

1. Установить Node.js LTS (https://nodejs.org) — и всё, больше ничего не нужно.
2. Скопировать папку проекта на VPS, создать `server/.env` с `BOT_TOKEN` и `APP_URL=https://app.твой-домен.ru`.
3. Собрать фронтенд: `cd app && npm install && npm run build`.
4. Установить сервер: `cd ../server && npm install`.
5. Запустить: `npm start` (или двойной клик по `start.bat`). Сервер слушает порт 3001
   (3000 занят первым сайтом bobkoved.ru).
6. Чтобы бот работал после перезагрузки VPS — добавить запуск в автозагрузку
   (Планировщик задач Windows: `node C:\...\server\src\index.js` при входе в систему).

## 16. Git и автообновление

### Как устроено

1. Проект хранится в Git-репозитории (ветка `main`).
2. Разработчик (или ИИ) вносит изменения и **загружает их на GitHub** (`git push`).
3. На сервере запущен `start.bat` → внутри него работает джоб **`_tools/autoupdate.js`**:
   - каждые **2 минуты** (настраивается `AUTO_UPDATE_INTERVAL` в мс) делает `git fetch origin`;
   - если в ветке появились новые коммиты — выполняет:
     `git pull` → `npm install` (если менялся `package.json`) → `npm run build` (если менялся `app/`)
     → перезапуск сервера.
4. Если в рабочей папке есть незакоммиченные изменения — обновление пропускается
   (чтобы не затереть локальную работу).

### Репозиторий (уже создан)

Проект загружен на GitHub: **https://github.com/Timitry100/xolodilnik** (ветка `main`, публичный).

Секретов в репозитории нет: `server/.env` (токен бота) и `server/data/` (БД) — в `.gitignore`,
они остаются только на сервере.

### Как обновить проект (после любых изменений)

```bash
git add -A
git commit -m "описание изменений"
git push
```

Джоб на сервере подхватит изменения автоматически (через ≤2 минуты):
`git pull` → пересборка → перезапуск сервера.

### Первичная установка на сервере (важно!)

Чтобы автообновление работало, проект на сервере должен быть **клонирован из Git**
(простое копирование папки с компьютера — автообновление не сработает, т.к. не будет `.git`):

```bash
git clone https://github.com/Timitry100/xolodilnik.git
cd xolodilnik
start.bat
```

При первом запуске `start.bat` сам создаст `server/.env` и попросит токен бота.
Дальше любые `git push` с компьютера будут подтягиваться на сервер автоматически.

### GitHub-токен

Токен GitHub хранится в файле **`_tools/github_token.txt`** (этот файл в `.gitignore` —
в Git и на GitHub не попадает). Используется скриптами `_tools/push_github.mjs` и др.
**НЕ выкладывать токен в `PROJECT.md` или другие коммитящиеся файлы** — репозиторий публичный,
и токен станет доступен всем. После потери/утечки токена — отозвать его на GitHub
(Settings → Developer settings → Tokens) и записать новый в `_tools/github_token.txt`.

### Настройка авторизации для пуша с этой машины

Пока на компьютере нет сохранённого доступа к GitHub. Рекомендуется один раз выполнить:

```bash
# способ 1 (проще): GitHub CLI

# способ 2: обычная авторизация git

```
